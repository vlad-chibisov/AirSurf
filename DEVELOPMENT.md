Developing AirSurf
=================

How AirSurf works under the hood, and what you need to know to change it. For installing and using the
app, see the [README](README.md).

The project has no dependencies. WebKit is not public on tvOS, so AirSurf uses private APIs. That's why
it can only be installed from Xcode, never through the App Store.

Interface
---------

The interface uses the tvOS focus engine throughout. Liquid Glass is used on newer Apple TVs. The Apple
TV HD (`AppleTV5,3`) and the first Apple TV 4K (A1842, `AppleTV6,2`) get a lighter blur instead, which
costs less to draw; see `BrowserTheme.m`. `BROWSER_MATERIALS=light` or `=glass` in the scheme's
environment forces one look or the other.

Video
-----

Pressing a player's full-screen button hands the video to the system player (AVPlayer) with the same
stream and position. This also works for players embedded from other sites (iframes), which is how most
film and series sites show video. The system player plays HLS (`.m3u8`) and MP4/MOV. Sites that only
serve DASH or WebM, or that protect streams with DRM, keep playing in the page, or not at all. YouTube is
one of these: it does not hand out plain streams.

- **Quality and voice-over**: most players change the stream itself when you pick these, so the new
  stream is what gets handed over. For players built on hls.js, the choice is applied in the system
  player's own track and quality selection instead.
- **Subtitles**: those that are part of the stream are in the system player's subtitle menu anyway.
  Those a player loads as separate files (WebVTT or SRT) are added to the stream as ordinary subtitle
  tracks, so they appear in the same menu in the system caption style, and the one that was on in the page
  is on. The menu gets one track per language (it names tracks by language only): the one you had on,
  otherwise the most complete one.
- **Media Source Extensions**: WebKit on tvOS doesn't have them, so in-page playback always goes through
  the system's HLS support. Players that need MSE used to stop with "browser not supported" or "update
  iOS". For those the app gives the player a stand-in and plays the same stream with the system's HLS
  support, so the player's menus work and the video plays in the page. Known players get this straight
  away; any other hls.js player that reports itself unsupported is reloaded once with it.
- When the system player can't open a stream, the app says so and the video can be watched in the page.

Video detection and the MSE stand-in live in `AirSurf/Resources/BrowserAgent.js`, a script the app
injects into every page. Site-specific fixes belong there too; this is also the only way to get the
effect of browser extensions, which WebKit on tvOS has no system for.

Ad blocking
-----------

Ad blocking uses WebKit's built-in content blocker, the same engine Safari's blockers use, so it costs
almost nothing at page-load time. The list is in `AirSurf/Resources/ContentRules-Ads.json` (about 3,600
domains) and is generated by `Tools/update_content_rules.py` from Peter Lowe's ad server list plus
`Tools/extra-ad-domains.txt` (ad networks common on streaming sites; `re:` lines are host patterns for
networks that rotate numbered domains). To refresh it, run
`python3 Tools/update_content_rules.py --download`, then rebuild.

Storage
-------

Apps on Apple TV may only write to their Caches folder, and their settings are capped at about 500 KB.
Compiled ad-block rules, open tabs, thumbnails, cookies and what sites save in the browser (local
storage, IndexedDB) therefore live in Caches, with small copies of tabs and cookies in settings in case
tvOS clears Caches.

App icon
--------

`swift Tools/render_app_icon.swift`, run from the repository root, draws the icon's three parallax layers
into the asset catalog and writes the README logo, `.github/logo.png`.

Testing in the Simulator
------------------------

The Siri Remote can't be scripted in the Simulator, so Debug builds accept launch arguments instead:
`-DebugURL <url>`, `-DebugClicks "x,y@seconds;..."`, `-DebugScroll "y@seconds"`,
`-DebugActions "newtab@1;tabs@3;hold@5;menu@7"`, `-DebugEval "js@seconds"` (result in the log). They do
nothing in Release builds.
